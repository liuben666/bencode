# BenCode Tool Call Engine - 需求规格

## 背景

BenCode 第一个里程碑（llm-tui-client）已交付纯对话能力：TUI 多轮流式对话、双 Provider、会话持久化。本模块为第二个里程碑：给 BenCode 装上工具系统。用户提问后，模型不再只能生成文字，而是能读文件、写文件、改文件、执行命令、查找与搜索代码，从聊天机器人变成真正能干活的 Agent。

核心闭环：模型在流式响应中识别出自己要用的工具 → BenCode 本地执行 → 结果作为工具结果消息回灌对话历史 → 模型据此产出最终回复。

本期明确只做单轮工具调用：模型拿到一次工具结果后收尾作答，自动循环（Agent Loop）留待下一期。

## 目标用户

- 希望让 AI 直接读写本地项目文件、执行命令完成实际任务的终端开发者
- 需要让 AI 在代码库中定位、检索、修改代码的用户
- 对工具执行有安全顾虑、要求危险操作先确认的谨慎型用户

## 能力清单

1. 定义统一工具接口：所有工具实现同一抽象，元信息包含名称、描述、参数结构与执行入口
2. 提供六个核心工具：读文件、写文件、改文件、执行命令、按模式查找文件、按内容搜索代码
3. 提供工具注册中心：集中登记工具、按名查找、分别导出为 OpenAI 与 Anthropic 两类 API 协议认得的工具清单
4. 工具执行具备超时保护：超时后终止执行并向模型返回结构化超时错误，程序不悬挂
5. 工具执行失败不崩溃：任何异常被捕获并包装为结构化错误结果回传模型，由模型自行调整策略
6. 改文件采用原文唯一匹配替换：匹配不到或匹配多处时返回指明原因与出处的错误，供模型修正后重试
7. 工具结果回灌前做长度截断保护，并在结果中标注截断信息与原始长度
8. OpenAI 协议适配器支持流式工具调用解析：调用参数以 JSON 片 fragment 形式分片到达时，正确聚合拼接为完整调用
9. Anthropic 协议适配器支持流式工具调用解析：从原生工具调用内容块中还原调用标识、工具名与完整参数
10. 工具调用与结果作为消息写入对话历史并回传 API，模型据此产出最终回复
11. 危险操作（写文件、改文件、执行命令）执行前需用户在 TUI 确认；读文件与搜索类工具直接执行
12. 用户拒绝执行时，拒绝信息作为结构化结果回传模型，模型可改用其他方案继续回答
13. TUI 以折叠卡片展示每次工具调用：默认折叠显示摘要行（工具名与状态），展开可查看参数与结果
14. 工具调用与结果消息随会话持久化，恢复历史会话后可正确回传 API 继续对话
15. 单轮边界：模型单次响应中的多个工具调用按顺序逐个执行并回灌；工具结果回灌后的收尾回复若再次请求工具，则不执行并在 TUI 明确提示

## 非功能要求

| 维度 | 要求 |
|------|------|
| 统一接口 | 新增工具只需实现工具接口并在注册中心登记，无需改动执行链路与 UI |
| 执行安全 | 危险操作必须经用户确认；拒绝语义明确回传模型而非静默丢弃 |
| 超时保护 | 工具执行有超时上限，超时后底层进程被终止，不残留 |
| 错误韧性 | 任何工具异常不影响主程序稳定性，均转为结构化结果 |
| 上下文保护 | 回灌结果有截断上限，避免单次工具输出撑爆模型上下文 |
| 双协议 | Anthropic 与 OpenAI 适配器均支持工具清单下发与流式调用解析 |
| 持久化兼容 | 会话 JSON 格式向后兼容，旧版本会话文件可正常加载展示 |

## 整体设计骨架

```
用户终端输入
     │
     ▼
  TUI 主对话界面（复用现有 ChatScreen）
     │  携带工具清单发起请求
     ▼
  Provider 抽象层（本期扩展：请求携带工具清单 + 流式解析工具调用）
     ├── Anthropic 适配器（原生工具调用内容块 → 统一工具调用事件）
     └── OpenAI 适配器（参数 JSON 碎片聚合拼接 → 统一工具调用事件）
     │  流式返回：正文 / thinking / 工具调用事件
     ▼
  TUI 工具调用处理（本期新增）
     ├── 折叠卡片展示（工具名 / 参数 / 结果 / 状态）
     └── 危险操作确认（写 / 改 / 命令 → 用户 y/n）
     │
     ▼
  工具层（本期新增）
     ├── 注册中心（登记 / 按名查找 / 导出双协议工具清单）
     └── 执行器（超时保护 / 异常包装 / 输出截断）
     │  结构化工具结果
     ▼
  结果回灌：工具调用与工具结果消息追加进对话历史并持久化
     │
     ▼
  Provider 发起第二次请求 → 模型产出最终回复 → 本轮结束
  （收尾回复若再次请求工具：不执行，TUI 明确提示 —— Agent Loop 留待下一期）
```

## Out of Scope（本期不做）

- Agent Loop：工具结果回灌后的自动多轮循环
- 多工具并发执行（单次响应多个调用仅按顺序执行）
- 确认策略配置化（如工具白名单、自动批准规则、always/never 选项记忆）
- 沙箱与文件系统权限控制（路径白名单、命令黑名单、系统提示词注入）
- 更多工具类型（联网搜索、子 Agent、MCP 协议接入等）
- 工具调用失败后的代码侧自动重试（错误结果回灌后由模型自行决定，不做程序内重试）
- Token 用量与计费统计
